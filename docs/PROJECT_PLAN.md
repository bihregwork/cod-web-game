# SDLC-план разработки веб-игры

Дата создания: 2026-07-20

## Summary

- Цель: разработать легкую веселую веб-игру, где героиня в деловом костюме с большим кошельком ловит падающие предметы, получает очки и теряет жизни за критичные ошибки.
- Процесс начинается с отдельного этапа **Discovery / Опрос и сбор информации**.
- После каждого этапа действует **Stage Gate**: результат фиксируется, заказчик принимает этап и подтверждает старт следующего.
- Стек предварительно: Vite + React + TypeScript, Canvas 2D, Netlify Functions + Netlify Blobs, Netlify.
- Стек окончательно утверждается только после Discovery и Requirements.

## Stage Gate Rule

- В конце каждого этапа Codex показывает результат этапа и краткий список ключевых решений.
- Результат записывается в соответствующие документы.
- Следующий этап начинается только после явного подтверждения заказчика.
- Если результат не принят, этап дорабатывается до принятия.
- Предложения Codex по открытым вопросам сначала выводятся в чат; в документы они записываются только после явного согласования заказчиком.

## Visual Approval Process

- В Discovery собираются визуальные ожидания и референсы.
- В Requirements фиксируются базовые требования к визуалу.
- В Design создаются `docs/VISUAL_BRIEF.md` и `docs/ASSET_PROMPTS.md`.
- Генерируются 2-4 визуальных направления и показываются на утверждение.
- Если варианты не подходят, замечания фиксируются, prompts обновляются, выполняется следующая итерация.
- В Development можно переходить только после утверждения визуального направления.

## Public Interfaces

- Игровой интерфейс: старт/игровой экран, HUD со счетом и жизнями, пауза, рестарт, экран окончания игры, ввод имени, таблица рекордов.
- API:
  - `GET /.netlify/functions/scores` - получить топ-10 рекордов.
  - `POST /.netlify/functions/scores` - сохранить `{ playerId, name, score }`.
- Конфиг игры: стартовые жизни, очки за предмет, скорость героя, скорость падения, частота появления предметов, рост сложности.

## Assumptions

- Язык интерфейса: русский.
- Первая версия без аккаунтов, мультиплеера, магазина и сложной системы уровней.
- Бэкенд нужен только для таблицы рекордов.
- Таблица рекордов использует анонимный локальный `playerId`; имя игрока является отображаемым именем, а не уникальным идентификатором.
- Размещение: публичная ссылка на Netlify.
- Каждый новый проект начинается с Discovery до проектирования, выбора стека и разработки.
