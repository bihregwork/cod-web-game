# API Contract / Контракт API таблицы рекордов

Дата создания: 2026-07-21
Статус: Accepted for current Design block

## Цель

Спроектировать API таблицы рекордов для v1: top-10, анонимный локальный `playerId`, лучший результат одного игрока и возможность вести несколько локальных профилей на одном устройстве.

## Хранилище v1

Для v1 используется связка:

- Netlify Functions как HTTP API;
- Netlify Blobs как простое key/value-хранилище для таблицы рекордов.

Причина: таблица рекордов содержит мало данных, часто читается и редко записывается. Такой вариант проще для первой публичной версии и подходит для размещения на Netlify.

## Принятые правила

- Таблица рекордов показывает только top-10.
- Используется анонимный локальный `playerId`.
- На одном устройстве может быть несколько локальных профилей: каждое новое имя получает свой `playerId`.
- Если игрок вводит уже существующее имя, используется прежний `playerId` этого локального профиля.
- Связка `имя -> playerId` хранится в `localStorage`.
- Для одного `playerId` хранится только лучший результат.
- Если новый результат ниже личного рекорда, `score` не обновляется.
- Если имя у существующего `playerId` было технически обновлено, имя можно обновить даже при более низком результате.
- Top-10 сортируется по `score desc`; при равенстве очков выше тот, кто набрал результат раньше.
- Публичный ответ API не возвращает raw `playerId`.

## Endpoints

| Метод | URL | Назначение |
|---|---|---|
| `GET` | `/.netlify/functions/scores` | Получить top-10 |
| `POST` | `/.netlify/functions/scores` | Сохранить результат игрока |

## GET `/.netlify/functions/scores`

Назначение: получить текущий top-10.

Query-параметры:

| Параметр | Обязательный | Назначение |
|---|---|---|
| `playerId` | Нет | Позволяет API отметить текущего игрока, если он попал в top-10 |

Пример:

```text
GET /.netlify/functions/scores?playerId=uuid-from-local-storage
```

Ответ `200`:

```json
{
  "scores": [
    {
      "rank": 1,
      "name": "Андрей",
      "score": 250000,
      "isCurrentPlayer": true,
      "updatedAt": "2026-07-21T13:00:00.000Z"
    }
  ]
}
```

## POST `/.netlify/functions/scores`

Назначение: сохранить результат игрока.

Запрос:

```json
{
  "playerId": "uuid-from-local-storage",
  "name": "Андрей",
  "score": 250000
}
```

Ответ `200`:

```json
{
  "accepted": true,
  "personalBestUpdated": true,
  "nameUpdated": true,
  "inTop10": true,
  "rank": 1,
  "scores": []
}
```

Поля ответа:

| Поле | Значение |
|---|---|
| `accepted` | Результат обработан API |
| `personalBestUpdated` | Новый результат стал личным рекордом для `playerId` |
| `nameUpdated` | Отображаемое имя было обновлено |
| `inTop10` | Игрок входит в текущий top-10 |
| `rank` | Место игрока в top-10 или `null`, если он не попал в top-10 |
| `scores` | Актуальный top-10 после обработки результата |

## Валидация

| Поле | Правило |
|---|---|
| `playerId` | обязательный UUID |
| `name` | 1-20 символов после `trim` |
| `name` | разрешены кириллица, латиница, цифры, пробел, дефис, underscore |
| `name` | управляющие символы запрещены |
| `score` | целое число от `0` до `999999999` |

## Ошибки

| Код | Когда |
|---|---|
| `400` | неверный `playerId`, имя или `score` |
| `405` | неподдерживаемый метод |
| `500` | внутренняя ошибка хранения |
| `503` | таблица рекордов временно недоступна |

Формат ошибки:

```json
{
  "error": {
    "code": "VALIDATION_ERROR",
    "message": "Некорректные данные результата"
  }
}
```

## Frontend fallback

Если сохранение результата не удалось:

- игра показывает сообщение `Рекорд временно не сохранен`;
- результат сохраняется как pending-result в `localStorage`;
- при следующем открытии игры или при повторной попытке открытия `Game Over` frontend пробует отправить pending-result еще раз;
- игровой процесс не блокируется из-за ошибки API.

## Статус реализации

- `netlify/functions/scores.ts` реализует `GET` и `POST` по этому контракту.
- `src/services/leaderboardApi.ts` работает с API-форматом `{ scores }` и ответом сохранения `{ accepted, personalBestUpdated, nameUpdated, inTop10, rank, scores }`.
- `src/services/playerIdentity.ts` хранит несколько локальных профилей `имя -> playerId`.
- `src/services/localLeaderboard.ts` используется как локальный fallback для обычного Vite-запуска и временной недоступности API.
- Pending-result сохраняется в `localStorage` и повторно отправляется при следующем запуске приложения.

## Визуальное поведение

- Текущий игрок в top-10 выделяется визуально через `isCurrentPlayer`.
- Отдельный личный лучший результат вне top-10 в v1 не показывается.
- На `Game Over` игрок вводит имя: существующее имя выбирает прежний локальный профиль, новое имя создает новый локальный профиль.
